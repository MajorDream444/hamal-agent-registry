# HAMAL Agent Registry

This repository is the versioned home for the AMA Solutions agent campus and HAMAL operating model.

Start with [the canonical handover](docs/AMA_Solutions_HAMAL_Agent_Campus_Canonical_Handover.md). It defines the 12 Mobs, 12 named leader personas, 144 numbered commander positions, how a visitor enters the campus, how work is routed, and which claims require verification before publishing.

## Current status

The 144 commander positions and Mob leader personas are a **designed registry**, not proof that 144 agents are deployed or available to hire. MobStack is a planning map for execution, not verified production runtime. The public service descriptions follow the 12 Mob catalog and AMA deep dives; any conflicting labels in other source files are documented in the handover.

## How to extend this registry

1. Keep `AGINT-001` through `AGINT-144` as stable identifiers.
2. Add an agent profile only with an owner, role, inputs, outputs, review gates, status, and evidence of deployment.
3. Mark statuses as `concept`, `prototype`, `pilot`, `available`, or `retired`.
4. Do not publish a hire or live chat action until its destination and human owner work.
5. Update the handover and dated changelog when Major approves a change to the operating model.

AMA Solutions owns the client relationship and delivery. Hanzo is the AI and infrastructure layer. Lux is a proposed provenance layer where needed. HAMAL is the coordinating model; MobStack is the planned execution harness.
